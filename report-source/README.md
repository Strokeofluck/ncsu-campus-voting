# Report authoring source

The current article and prototype share the white publication palette in `palette.css`. Prepare them with `python scripts/prepare_article_content.py --project-dir <article-project>` and `python scripts/prepare_prototype_content.py --project-dir <prototype-project>` before building. Both apply the palette through the supported `src/theme.css`, including `--fixed-theme-scheme: light`, so system dark mode does not darken the publication. References use matching colors in `article-references.css`.

`snapshot.json` is the complete aggregate-only reviewed snapshot with stable artifact ID. `report/ReportContent.jsx` and `report/report.css` are the authored content. The compiled root `index.html` uses the verified Codex Data shared runtime; it requires the root content-addressed snapshot JSON sidecar.

`scripts/build_party_trends.py` adds `party_daily` without changing the existing queries. It verifies original CSV hashes, checks unique accepted identifiers locally, counts each matched early ballot by source return date and voter party registration, and computes running totals. All 432 day/scope/cohort totals reconcile to the prior daily query; all-age party totals reconcile to the demographic query. Only aggregate rows are exported to `matched_party_daily.csv` and `party_trends.json`. `refresh_report_snapshot.py` reruns this step on future refreshes. Three simultaneous year charts (`voting-party-trend-2022`, `voting-party-trend-2024`, and retained `voting-party-trend` for 2026) use shared location and age controls, aligned early-voting days, and a common ceiling. The age menu uses nonoverlapping bands; the legacy 18–22 sensitivity rows remain in the data. `voting-party-totals` lists all three years together. Labels name Talley Student Union or Western Boulevard Business Services; canonical scope keys remain unchanged. Registered party is not candidate choice, and unaffiliated voters are a separate series.

To revise in Codex, use the installed Data app preparer with `--surface report --snapshot report-source/snapshot.json --output <new-project>`, read its AGENTS.md, copy these report files into `src/content/report/`, preserve the existing snapshot and artifact ID in `src/data.json`, and build with the installed `data-app.mjs build --project-dir <project> --separate-data`. Copy its verified `dist` files to the repository root. Keep all data and date-specific narrative synchronized on refresh. For a portable offline file use `data-app.mjs export-offline` and deliver the result locally; the deployed split build is retained in Git.

After rebuilding and validating the comparison, run `scripts/audit_campus_figures.py`, `scripts/build_reference_page.py` and `scripts/refresh_report_snapshot.py`. The audit reads the comparison's current matched dates, and the report derives displayed date ranges from those rows. Refresh the README, reporting notes, references freshness and saved chart images before publication. Keep `buildStatus` as `updating` during checks and set it to `complete` for the final verified build.

Same-day-registration counts and all-ballot counts are compared together in `voting-registration-growth`; its baseline follows the main year selector. The campus count table also shows same-day share. Shares divide same-day-registration ballots by all site ballots, all ages. `refresh_report_snapshot.py` refreshes `same_day_registration_comparison.csv` through `build_registration_comparison.py`; `build_figure_sources.py` supplies exact share and share-change targets using the existing verified count selections. Keep the distinction between count growth and share change explicit.

`voting-denominator-clarity` distinguishes college-age site count, within-site age mix and share of Wake's same-age ballots. `voting-expanded-counts` shows counts and changes for all three scopes and four cohorts using the main baseline selector. `build_comparison_metrics.py`, also invoked by `refresh_report_snapshot.py`, exports 24 comparisons with explicit scope and county denominators. The expansion-plan section marks uncalculated cross-tabs and missing population or accessibility evidence as further work, not current findings.

`figure-source.html` in this source folder is the standalone evidence-page template. Run `python scripts/build_figure_sources.py` from the repository after refreshing validated data; it writes the public root evidence page and aggregate JSON. Publish those files alongside the compiled report. The original report identity remains unchanged.

Run `python scripts/build_source_previews.py` to rebuild the exact figure targets and original-file previews together. It verifies the ZIP, extracted Wake CSV and archive member against the recorded hashes; exports original filenames and CSV header plus bounded grouped extracts of five non-identifying source columns; and checks every selected total against the reviewed report data. Publish `data/processed/comparison/source_previews.json` alongside the evidence page. The live NCSBE directory iframe loads only when expanded. Raw voter-level files remain ignored.

The standalone `csv-viewer.html`, `csv-viewer.js` and `csv-viewer-worker.js` render actual original records in the browser, embedded in each figure reference. On explicit load, the worker range-reads NCSBE's ZIP directory and Wake CSV member, inflates it with vendored Pako, checks the member's SHA-256 against the report snapshot, and indexes the original CSV for pagination. The default view selects the figure's records and seven source columns; all records, all columns and original CSV text are available. Updated live files are clearly marked when their hash differs. The viewer does not upload, persist or publish individual records. Ship these files and `vendor/` unchanged alongside the report; no main report build is needed to update this supplemental viewer. Pako 1.0.11 is distributed under its MIT/Zlib licenses, included in `vendor/`.

`csv-proof.html`, `csv-proof.js`, `csv-proof-model.js` and `csv-proof-worker.js` add a three-tab calculation preview embedded in each figure source. The shared model recursively resolves the figure's inputs, including denominators omitted from its numerator selection. Each distinct count is recounted independently from original records. Pagination retains original CSV record numbers and adds a contribution of 1 and running count for matching rows. The worker reuses the original viewer's ZIP and CSV utilities. It loads only on explicit request. Source-hash differences and count differences remain visible and prevent a verified-snapshot label. Run `node scripts/test_csv_proof.cjs` to test all 211 calculation graphs, CSV quoting and newlines, window filtering, separate count selections, pagination and changed-source reporting.

`python scripts/build_csv_calculation_inputs.py --output-dir <local-output-directory>` checks saved Wake CSV hashes, recounts campus records and exports a local `campus_age_source_groups.csv`. It preserves seven original field values and groups identical records with a matching count. The separately supplied local workbook has this grouped source as its first tab and actual SUMIFS, share, growth and difference formulas on its second tab. Neither the workbook nor the detailed grouped extract is published in this repository. The public `campus_age_calculations.csv` contains only the same eight aggregate result rows and literal formula text, with shares, growth and percentage-point changes matching the report’s one-decimal display. Refresh the local workbook and public calculation CSV whenever the snapshot changes. Do not publish voter-level source caches or detailed extracts without explicit approval.

The primary download uses `csv-excel-worker.js`, `csv-excel-export.js`, `csv-original-copy.js`, `csv-zip-stream.js`, `csv-excel-package.js`, `csv-excel-template.json` and vendored Pako/JSZip. The ZIP separates exact government bytes in `01 Original files/{year}/`, Excel in `02 Working copy/`, and the source manifest in `03 Source checks/`. Eight workbook tabs start with source metadata and three full Copy tabs: every row, every original column and header, original order, and text values preserving leading zeros. They are preloaded copies, not external queries. A seven-field campus extract links to the matching Copy cells using real blank-preserving formulas; added year and original CSV record numbers retain provenance. Filter flags, running counts, COUNTIFS totals and share/change formulas follow. Editing referenced Copy values updates the later tabs; extraction membership is fixed and requires rebuilding after site-membership changes. All original hashes and age/registration totals must match before export. The Artifact Tool template contains layout and tested formulas with no voter input rows; streaming compression fills its full-copy worksheets without building gigabytes of XML in memory. Cached results and automatic full recalculation are retained. No macros or data uploads are used. Ship all these assets and both vendor libraries/licenses. The original CSV parser preserves literal quotes in unquoted fields, quoted commas/newlines and escaped quotes. The older grouped local workbook remains separate.

`report-source/references.html` is the portfolio-style reporting-reference template; `reference-library.html` preserves the earlier location, validation, Election Day and reporting sources. Run `python scripts/build_reporting_references.py` to generate root `references.html` from the current comparison and exact figure records. Publish it with `references.css`, `references.js` and the shared CSV assets. `CsvProofView.create` mounts native inline controls with prefixed IDs, opening on Calculation with one page scroll. Figure selection replaces the active calculation and resets its recount state. The default comparison is 2022 versus 2026; the alternate 2024 baseline updates every displayed number and calculation target. No original voter records are embedded in this reference page. `python scripts/test_reporting_references.py` verifies both baselines with exact fractions, source targets, local assets, unique IDs, absence of iframe framing and retained links. The main report build and identity are unchanged by this supplemental-page revision.

`build_sdr_trends.py` recounts 1,152 daily registration aggregates from the hash-verified originals, with same-cohort ballot denominators. Daily subset, age and scope partitions and existing all-age totals reconcile. `refresh_report_snapshot.py` rebuilds this query after party denominators. The new chart and both final-summary tables share the party section’s location and age filters. Final summaries show exact counts, shares, absolute/relative growth and unrounded percentage-point changes against both baselines. Run `test_sdr_trends.py` after refresh. Only aggregate rows are published.

`build_geography.py` independently aggregates recorded residential `precinct_desc` and `voter_zip` by age and year, splitting named-site and other-Wake ballots. Every dimension partitions each reviewed cohort exactly. Missing area/year labels remain null; cohort zeros within observed areas stay zero. `GeographyExplorer.jsx` provides independent age/geography controls, area search, count/share charts for the top ten matching areas, and a paginated full table. Shares use all same-area/cohort accepted early ballots, not registered-population denominators. Only aggregate geography fields are exported; no names, addresses or IDs. Run `test_geography.py` after refresh.

The precinct map is in `PrecinctMap.jsx`, using vendored Leaflet 1.9.4, its license and documented compatibility patches under `report/vendor/leaflet`. `download_precinct_map_sources.py` retrieves public Wake GIS polygons and NC State building coordinates, retaining URLs, hashes, layer dates and attribution in `precinct_map_sources.json`. `build_precinct_map.py` binds those source snapshots without changing any ballot query. Map shading is same-area named-site share for the selected year and cohort; current outlines are explicitly labeled and unmapped ballots remain in full tables/CSV. Selection filters the existing geography chart/table. Run `test_precinct_map.py`. Basemap street tiles load from Esri; if unavailable, polygons, pins and counts remain usable. The map follows the housing article’s light street-map and hover-detail presentation, with a native source wrapper.
